# 🖼️ `/readimg` 圖片閱讀使用指南

本指南只講一件事：**怎麼讓澪「看到」你發的圖片，並以角色身分回應。**

`/readimg` 會：
- 用**本地 ollama + Gemma4**（多模態模型）分析圖片，產出結構化描述
- 把描述注入 prompt，讓角色真的「看到」這張圖再回話
- 支援**直接附圖**，或**指定讀取頻道裡的上一張圖**
- 分析結果寫入 `image_logs/`，方便管理員追查

## 一、快速上手

```
/readimg
```

就這樣。**不用附任何東西**——澪會自動去翻這個頻道**最近 20 則訊息**，找到**你自己**發的第一則圖片來分析。

適合「剛才那張圖，你再看一下」的情境。

---

## 二、參數說明

| 參數 | 型別 | 必填 | 說明 |
|------|------|------|------|
| `image` | 附件（圖片） | 否 | 直接附上要分析的圖片。附了就優先用這張，不會去翻歷史 |
| `message` | 文字 | 否 | 你的留言／提問。會一併傳給角色，例如「這張圖裡的人是谁」 |

**兩個都不填** → 讀你在頻道最近 20 則訊息中的第一張圖。

**只填 `message`** → 讀上一張圖，並把你的問題當成提問依據。

---

## 三、兩種讀圖方式

### 方式 A：直接附圖（最精準）

```
/readimg image:（附上圖片） message: 這傢伙的表情是什麼意思
```

### 方式 B：讀上一張圖

```
/readimg message: 她現在在想什麼
```

**注意**：讀的是「**你自己**」在這個頻道最近 20 則訊息裡的**第一個有附件的訊息**。所以：

- **只會讀你發的圖**。別人發的圖不算
- 機器人自己發的圖也不算（例如 `/tarot` 抽到的塔羅牌）
- 這 20 則裡**你自己沒有任何圖** → 會直接報錯
- 有多張圖 → 取**最新的那一張**（往回找先撞到的）
- 一則訊息有多個附件 → 只取**第一個**
- **跨頻道無效**，`/readimg` 只看自己所在的那個頻道
- 圖片必須在**最近 20 則**以內，久了就讀不到

### 兩種方式的差異

| | 方式 A（附圖） | 方式 B（讀上一張） |
|---|---|---|
| 圖片出處 | 你在指令上附的 | **你自己**先前在頻道發的 |
| 找圖範圍 | — | 最近 20 則訊息中的第一個有附件的訊息 |
| 回覆引用 | 引用你的指令訊息 | **引用原本那則有圖的訊息** |
| 出處標示 | `**你** 分享了一張圖片` | `**你** 分享了一張圖片` |
| 圖片會再出現一次嗎 | 不會 | **不會** |

> 兩種方式**都不會**把圖片重新貼一次——那張圖本來就已經在頻道裡了，重貼只是洗版。

## 四、它到底做了什麼

```
你下 /readimg
   ↓
取得圖片（附件 或 翻最近 20 則訊息找自己的圖）
   ↓
算圖片 MD5 → 查快取（5 分鐘內重複圖直接沿用）
   ↓
┌─ 沒快取 ─────────────────────────┐
│ 1. 縮小到長邊 768px、轉 JPEG(q80) │
│ 2. 送本地 ollama + Gemma4 分析    │
│ 3. 剝掉 <thinking> 標籤            │
│ 4. 存進快取                        │
└────────────────────────────────────┘
   ↓
把結構化描述注入 Phase 2 prompt
   ↓
附上最近 15 則訊息當上下文
   ↓
Phase 2 生成角色回覆（會套用剝除規劃／標記／HTML／（正文））
   ↓
回覆（不重貼圖片）+ 寫入 image_logs/YYYY-MM-DD.txt
```

## 五、讀出來的描述長什麼樣

Gemma4 被要求固定輸出這個結構：

```
[識別] 如果你認得出這是什麼角色、作品、梗圖、或 meme，直接寫出名稱。不確定就寫「不確定」。
[類型] 角色/場景/物品/其他
[描述] 一句話描述圖片內容
[表情] 角色的表情（如適用）
[姿勢] 角色的姿勢（如適用）
[環境] 背景環境（如適用）
[情緒] 整體氛圍
```

這段會以「【用戶分享的圖片分析結果】」為標題塞進 prompt，角色就是靠這段「看到」圖片的。

**模型看不到的細節**：很小的字、遠景的細節、臉部細微表情、圖中圖裡的文字（只能大致描述）。它是**本地 12B 模型**，不是雲端旗艦視覺模型，辨識度有上限。

## 六、速度與快取

| 情況 | 預期耗時 |
|------|----------|
| 第一次讀這張圖 | **約 30～60 秒**（首次還要載入模型，可能更久） |
| 5 分鐘內再讀同一張圖 | **幾乎瞬間**（直接用快取） |

**快取機制**：以圖片內容的 MD5 當 key，有效期 **300 秒（5 分鐘）**。
同一張圖重複讀會省下時間；但 ollama 重啟或機器重開後快取會消失。

> 分析期間 Discord 會顯示「正在輸入…」，這是正常的，**不要重複下指令**，否則會排隊。

---

## 七、回覆規則

`/readimg` 的回覆會走和其他訊息一樣的清理流程：

- 剝除 `<planning>...</planning>`
- 剝除 `MEM:` / `LEARN:` 標記
- 剝除 HTML 標籤
- 剝除 `（正文）` 標記
- 超過 1900 bytes 會截斷

**頻道風格自動判斷**：若頻道名稱或主題包含 `討論` / `中之` / `ooc` / `meta` / `後台` / `幕後` / `策劃` / `閒聊`，會用**中之人（OOC）**較寬鬆的語氣；否則用**沉浸式（IC）**語氣。

## 八、⚠️ 重要限制

### 1. 讀圖時**不會載入記憶與世界觀**

這是很多人會踩到的雷。`/readimg` 呼叫 Phase 2 時，記憶、世界觀、劇情任務、伺服器規則**全部是空的**。

意思是：**澪讀圖時不知道你們的劇情走到哪、也不知道那些設定**。它只根據「最近 15 則訊息」＋「這張圖的描述」來回話。

- ✅ 適合：看圖講話、針對圖片內容互動
- ❌ 不適合：期待它引用長期記憶或設定來分析圖片

> 需要「讀圖 ＋ 完整記憶」一起生效的話，得走一般訊息流程（把圖一起貼在訊息裡），而不是用 `/readimg`。

### 2. 只讀得到**你自己在最近 20 則訊息內**發的圖

超過就會回報找不到圖片。而且**別人發的圖不會被讀取**——只認你本人的。

### 3. 圖片會被**縮小到長邊 768px**

這是為了避免逾時（gemma 的 vision 是切 tile 看的，768px 約 4 個 tile，比 1024px 快近半）。副作用是**高解析度圖片的細節會遺失**。想看清楚小字，請自己裁切／放大後再傳。

### 4. **一次一張圖**

不支援一次傳多張。指令的 `image` 參數只吃一個附件。

### 5. 需要**本地 ollama 正在跑**

且已下載 `gemma4:12b` 模型。若 ollama 沒開或沒拉模型，會直接報錯。

### 6. 圖片會**留在你的機器上**

圖片不會上傳到任何雲端 API，只送給本機的 ollama。但分析描述與 AI 回覆會寫進 `image_logs/`（該目錄已在 `.gitignore` 中，不會被 commit）。

## 九、錯誤處理

| 看到什麼 | 代表什麼 | 怎麼辦 |
|----------|----------|--------|
| `❌ 找不到你的圖片…` | 最近 20 則訊息裡你沒有發過任何圖 | 直接在指令上附圖（方式 A） |
| `❌ ollama 套件未安裝` | 環境缺套件 | `pip install ollama` |
| `❌ 圖片分析逾時（180s）…` | 圖太大，或 ollama 還在載入模型 | 等一下再試；或先縮小圖片 |
| `❌ 圖片分析失敗: …` | 其他例外（見伺服器 log） | 請管理員查 log |
| `❌ Phase 2 呼叫失敗：…` | 生成回覆時出錯 | 請管理員查 log |
| `❌ (this log)` / 回覆是「（...）」 | 圖片分析回空 | 換一張圖試試 |
| 卡在「正在輸入…」很久 | ollama 首次載入模型 | 正常，等它跑完 |

**管理員查 log**：`error_logs/` 與 `image_logs/`。

## 十、常見問題（FAQ）

**Q：可以讀別人發的圖嗎？**
不行。`/readimg` 只會讀**你自己**發的圖。别人發的圖、以及機器人自己發的圖（例如塔羅牌）都會被略過。

**Q：那我看到別人發的圖，想讓澪評論怎麼辦？**
兩種方式：
- 把那張圖**存下來，用 `/readimg` 附上去**（方式 A，最可靠）
- 或者直接在有那張圖的訊息下面打字讓澪回覆——但走的是一般訊息流程，**不會有圖片分析**

**Q：為什麼不把圖再貼一次？**
因為那張圖已經在頻道裡了。重貼只是洗版，浪費頻道空間。所以設計上直接引用原本那則訊息。

**Q：讀上一張圖，會不會讀到我自己剛剛貼的圖？**
會，往回找第一個撞到的就是最新的。如果那張不是你想要的，用方式 A 直接附圖最準。

**Q：圖片分析要收費嗎？**
不用。走本地 ollama，沒有 API 成本，也不會把圖片傳到雲端。

**Q：`/readimg` 會影響澪的記憶嗎？**
不會。這個指令**不寫入記憶**，也不跑記憶召回。它只是「看圖 → 回話」。

**Q：同一張圖一直重複分析，會不會浪費資源？**
不會，5 分鐘內有快取。

**Q：能不能指定只看圖片、不要再回話？**
不能，目前一定要回話。
